# 装备系统多 Pass 阴影与武器渲染设计文档

> 目标：在当前 GPU 换装架构下，用 **多 Pass Shader** 做「贴合轮廓的脚底阴影」，基于 **全局地面基准 + 帧内脚部像素位置** 控制阴影，而不是靠动画名字。  
> 同时讨论：**武器是否并入 Shader 管线** 与 **保留子对象层级（斗篷等）** 的混合方案。

---

## 1. 设计目标与约束

- **阴影外观**
  - 阴影紧贴角色轮廓（包括服装、头盔等最终外观），不是简单椭圆。
  - 阴影始终「贴地」，不跟着角色跳起来。
  - 阴影大小/透明度基于「角色在帧中的垂直位置」（脚离地高度），而不是字符串动画名。

- **实现方式**
  - 使用现有 `EquipmentSystem/EquipmentUV` Shader，扩展为 **多 Pass**：
    - Pass 0：绘制阴影（Ground Shadow）。
    - Pass 1：绘制角色本体 + GPU 换装（现有逻辑基本保留）。
  - 不依赖 Animator 的动画 Bool 名字来判断「跳跃」，而依赖帧数据里的 **脚部像素位置 + 全局地面基准**。

- **层级 & 特殊子对象**
  - **仍然允许子对象 SpriteRenderer 存在**（斗篷等特殊动画可走传统贴图模式）。
  - 武器可以有两种方案：
    - 维持「武器子对象 SpriteRenderer + 专用 Shader（可带自身阴影）」。
    - 更激进：扩展 UV Map 与 Shader，把武器并入同一个 `EquipmentUV` 渲染管线（复杂度明显更高，建议后期再做）。

## 2. 数据设计：全局地面基准 + 帧内高度

### 2.1 全局地面基准（CharacterFrameData）

**动机：**

- 你已经保证所有动画的「地面位置」是一致的（比如 32×32 帧内某一条 y 像素）。
- 不希望每个动画单独配置基准帧，而是一个全局基准。

**推荐新增全局配置（示意）**

放在 [CharacterFrameData](cci:2://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Data/CharacterFrameData.cs:330:4-408:5) 中，和 `headExpandUp` 等处于同一层级：

- **`groundPixelY`**
  - 含义：所有动画中，角色「站在地上」时，脚底（或脚跟）所在的 **帧内 y 像素坐标**。
  - 坐标系：与 `BodyPartPixel.position` 相同（左下或左上视你工具的约定，保持统一即可）。
- （可选）**`maxAirHeightPixels`**
  - 含义：设计上角色「离地」的最大像素高度，用来做 0~1 的归一化。
  - 如果不配置，可以用 `frameSize.y` 的一部分估算（比如 8 像素）。

> 你可以在 [FrameDataEditor](cci:2://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Editor/FrameDataEditor.cs:18:4-3023:5) 的「全局配置」区域增加这两个字段的 Inspector，方便美术/自己调整。

### 2.2 帧级「离地高度」的计算

**现有可用数据：**

- [FrameData.GetSinglePixelPart(CharacterBodyPart.LeftFoot/RightFoot)](cci:1://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Data/CharacterFrameData.cs:212:8-219:9)
  - 返回 [BodyPartPixel](cci:2://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Data/CharacterFrameData.cs:88:4-105:5)，包含：
    - `position`：该脚在当前帧 32×32 内的像素位置。
- `AnimationData.frameSize`：统一是 32×32。

**高度计算思路：**

1. 对当前帧：
   - 从 `_cachedFrame` 中取：
     - `leftFoot = GetSinglePixelPart(LeftFoot)`
     - `rightFoot = GetSinglePixelPart(RightFoot)`
2. 计算当前帧的「实际接触地面 y」：
   - 可以用两只脚的 **最小 y** 或 **平均 y**：
     - `footY = min(leftFoot.position.y, rightFoot.position.y)` 或平均。
3. 使用全局地面基准 `groundPixelY`：
   - 离地像素数（注意你的像素坐标方向）：
     - 如果 y 往上增大：`hPix = groundPixelY - footY`  
       - 脚画得越高（越「离地」），`hPix` 越大。
   - 把 `hPix` 映射到 0~1：
     - `h01 = clamp(hPix / maxAirHeightPixels, 0, 1)`

**不保存到资产 vs 保存到 [FrameData](cci:2://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Data/CharacterFrameData.cs:155:4-220:5)：**

- **方案 A（推荐简化）**：**运行时计算**，不修改 [FrameData](cci:2://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Data/CharacterFrameData.cs:155:4-220:5) 结构。
  - 只依赖现有 `BodyPartPixel.position` 与全局 `groundPixelY`。
  - [EquipmentRenderer.Refresh()](cci:1://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Runtime/EquipmentRenderer.cs:327:8-394:9) 里有 `_cachedFrame`，可以直接计算。
- 方案 B：离线预计算 `shadowHeight01` 存入 [FrameData](cci:2://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Data/CharacterFrameData.cs:155:4-220:5)，优点是运行时简单，缺点是多一类数据维护。

综合你现在的编辑器复杂度和更新频率，**更建议先用运行时计算**，如果将来发现需要做手工微调，再考虑把 `shadowHeight01` 存回 [FrameData](cci:2://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Data/CharacterFrameData.cs:155:4-220:5)。

## 3. 运行时逻辑：EquipmentRenderer 中的阴影参数

### 3.1 计算阴影高度

在 [EquipmentRenderer.Refresh()](cci:1://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Runtime/EquipmentRenderer.cs:327:8-394:9) 中，你已经拿到了：

- [_cachedFrame = frameData.GetFrameData(_currentAnimName, _rowIndex, _frameIndex);](cci:1://file:///c:/Users/zhuagenbao/Desktop/MiniCharacterCreator-main/test/Assets/Scripts/EquipmentSystem/Data/CharacterFrameData.cs:370:8-378:9)
- `_currentAnimData.frameSize`。

可以在「设置 UV Map 贴图」之后、武器刷新之前/之后增加一段逻辑：

- 从 `_cachedFrame` 得到当前帧左/右脚像素位置。
- 用 `CharacterFrameData.groundPixelY` 计算 `hPix` 和 `h01`。
- 将以下信息写入材质：
  - `_ShadowHeight01`：0 = 脚完全落在地面；1 = 达到预设最高离地高度。
  - （可选）预计算好的：
    - `_ShadowScaleX` / `_ShadowScaleY`
    - `_ShadowAlpha`

> 关键点：**这里完全不需要知道「动画名」是不是 Jump，只需要看脚在 32×32 中画得多高**。

### 3.2 世界空间与本地空间的基准

在 Shader 的阴影 Pass 里，需要判断「阴影压到哪一条 Y=const 上」。

方案可以分两种：

- **方案 1：完全在 Shader 里做本地空间→地面投影**
  - 增加一个属性 `_ShadowGroundLocalY`：
    - 含义：在对象本地坐标中，地面所在的 Y。
  - C# 中根据 `groundPixelY` 和 Sprite 的 Pixels Per Unit 计算这个值。
  - 顶点阶段把角色顶点投影到这个 Y 上（加上 `_ShadowHeight01` 的影响）。

- **方案 2：简单压缩 + 固定偏移**
  - 不做精确的像素到单位映射，只规定「阴影永远在角色 pivot 下方某个常量偏移」。
  - `_ShadowHeight01` 只影响缩放和透明度，不移动阴影 Y。
  - 更简单，但不那么物理严格；对 8×8 像素角色来说通常也够用。

你现在的素材是 32×32 + 8×8 居中，pivot 很可能在 32×32 的中线附近。  
如果你希望「脚正好踩在世界 Y=0 这种绝对地面线」就选方案 1；如果只要大致效果，可以用方案 2。

## 4. Shader 设计：EquipmentUV 多 Pass 阴影

### 4.1 新增 Shader 属性（建议）

在 `Properties` 和 CG 变量中增加若干属性（命名可自调）：

- **开关 & 颜色**
  - `_ShadowEnabled`（Float；0/1）
  - `_ShadowColor`（Color；深灰，如 `(0, 0, 0, 1)`）
  - `_ShadowAlphaBase`（Float；基础透明度）

- **基于高度的动态参数**
  - `_ShadowHeight01`（Float；由 C# 计算并写入）
  - `_ShadowScaleMin` / `_ShadowScaleMax`（Float；控制最小/最大尺度）
  - `_ShadowAlphaMin` / `_ShadowAlphaMax`（Float；控制最小/最大透明度）

- **位置相关（可选，方案 1 才需要）**
  - `_ShadowGroundLocalY`（Float；对象本地坐标下的地面 Y）
  - `_SpriteHeightWorld` 或类似参数，用于从像素差换算到世界距离（如有需要）。

### 4.2 Pass 结构

现在只有一个 Pass，可以扩展为：

- **Pass 0：阴影 Pass**
  - Tags 同样是 Transparent。
  - ZWrite Off，Blend 可为 `SrcAlpha OneMinusSrcAlpha`。
  - 顶点函数：
    - 从 `appdata.vertex` 变换到对象空间→投影到 `_ShadowGroundLocalY` 附近。
    - 在 X 方向保持不变，Y 压缩再偏移。
    - 缩放、透明度根据 `_ShadowHeight01` 插值。
  - 片元函数：
    - 只关心「轮廓」：需要一个 alpha mask。
    - 取 mask 的两种方式（详见 4.3）。

- **Pass 1：现有角色渲染 Pass**
  - 基本保持现有 `frag` 逻辑不变。
  - 支持你现在所有的 Body/Head UVMap + Cloth/Hair/Beard/Helmet。

### 4.3 阴影轮廓的来源（核心）

要做到「贴合轮廓」，关键是阴影 Pass 的 alpha mask 要来自 **最终角色合成后的轮廓**，而不是单纯 `_MainTex`。

可选方案：

- **方案 S1：复用现有合成逻辑（推荐）**
  - 阴影 Pass 中，重复（或重用）`ApplyBodyLayers` / `ApplyHeadLayers` 的采样逻辑：
    - 按当前帧的 UVMap 和装备/外观数据，计算一次 `finalColor` 或至少 `finalAlpha`。
  - alpha 用 `finalColor.a`：
    - 包含身体原始 alpha + 头盔/头发扩展区域的 alpha。
    - 阴影轮廓自然随换装、头盔变化。
  - 缺点：阴影 Pass 成本接近再跑一遍角色合成，但你的分辨率极低（32×32），可以接受。

- **方案 S2：只用 `_MainTex` alpha（简化）**
  - 阴影轮廓只认原始身体 spritesheet 的 alpha，不考虑衣服、头盔扩展。
  - 实现简单，但穿了大盔甲阴影还是瘦身体轮廓。

鉴于你的目标是「贴合轮廓」，更建议 S1。

## 5. 武器渲染：Shader 图层 + 子对象序列帧混合方案

### 5.1 核心问题：手必须在武器前面

在当前架构下：
- 身体 + 手是 `EquipmentUV` 合成的一张 `SpriteRenderer`
- 武器是子对象 `SpriteRenderer`
- `sortingOrder` 只能控制**整个 Renderer** 的前后关系

如果想实现「身体在后、武器居中、手在最前」，只靠 `sortingOrder` 做不到。

**解决方案**：把武器也纳入 `EquipmentUV` 的合成流程，在 Shader 里控制绘制顺序：

1. 先画身体基底
2. 再画武器图层
3. 最后画手部区域 → **手自然覆盖在武器上**

### 5.2 混合模式：Shader 武器图层 + 子对象序列帧

为了兼顾灵活性，采用**自动切换**的混合方案：

| 情况 | 渲染方式 | 武器子对象状态 |
|------|---------|---------------|
| **当前动画没有武器序列帧** | 由 `EquipmentUV` 的武器图层绘制 | `sr.enabled = false`（仅做挂点/特效） |
| **当前动画有武器序列帧** | 由子对象 `SpriteRenderer` 绘制 | `sr.enabled = true`，Shader 武器层关闭 |

**判断条件**：直接复用现有的 `TryGetSequenceSpriteByKey()`：
- 能拿到序列帧 → 用子对象模式
- 拿不到 → 用 Shader 武器层模式

**不需要额外配置开关**，完全数据驱动。

### 5.3 Shader 武器图层设计

在 `EquipmentUV.shader` 中新增：

**Properties:**
```hlsl
[Header(Weapon Layer)]
_WeaponTex ("Weapon Texture", 2D) = "white" {}
_WeaponRect ("Weapon Rect", Vector) = (0,0,1,1)
_EnableWeapon ("Enable Weapon", Float) = 0
```

**合成顺序（在 `ApplyBodyLayers` 中）:**
```
1. Torso (服装/斗篷)
2. Weapon (武器图层) ← 新增
3. LeftHand / RightHand (手/手套) ← 手在武器后面画，自然覆盖武器
```

**武器区域标记**：
- 在 BodyUVMap 中新增 `ID_WEAPON = 0.8`
- 武器区域的像素会采样 `_WeaponTex`

### 5.4 子对象的保留价值

即使在 Shader 武器层模式下，武器子对象仍然保留：

- **挂点功能**：用于挂载特效、Trail、Collider 等
- **序列帧模式**：特殊攻击动画时启用，画面完全由美术控制
- **调试**：可以看到武器的逻辑位置

### 5.5 实现要点

**EquipmentRenderer 中的逻辑:**

```csharp
void RenderWeapon(EquipmentData equip, SpriteRenderer sr, ...)
{
    var seqSprite = equip.TryGetSequenceSpriteByKey(_currentAnimName, _rowIndex, _frameIndex);
    
    if (seqSprite != null)
    {
        // 序列帧模式：子对象画武器，Shader 武器层关闭
        sr.enabled = true;
        sr.sprite = seqSprite;
        _shaderMaterial.SetFloat(EnableWeaponProp, 0);
    }
    else
    {
        // Shader 武器层模式：子对象隐藏，武器由 Shader 画
        sr.enabled = false;
        var weaponSprite = equip.GetSpriteByRow(_rowIndex);
        if (weaponSprite != null)
        {
            _shaderMaterial.SetTexture(WeaponTexProp, weaponSprite.texture);
            _shaderMaterial.SetVector(WeaponRectProp, SpriteUtils.GetUVRect(weaponSprite));
            _shaderMaterial.SetFloat(EnableWeaponProp, 1);
        }
    }
}
```

## 6. 与斗篷等“传统贴图模式”的兼容

- 部分特殊装备（斗篷、翅膀、大旗等）：
  - 可能需要复杂顶点动画、骨骼/布料模拟、独立的 sorting 层。
  - 更适合作为 **独立子对象 SpriteRenderer**。
- 阴影处理方式：
  - 斗篷本身若只作为视觉附属，其阴影可以不单独投（简化）。
  - 若一定要斗篷阴影：
    - 可以与武器类似，为斗篷 SpriteRenderer 配一个简单阴影 Shader。
    - 或者单独挂一个「斗篷阴影」子对象，使用简单椭圆/模糊长条即可。

多 Pass 的 `EquipmentUV` 专注于「角色身体主体 + 头部 + GPU 装备」，避免把所有花哨特效都塞进去，保持职责清晰。

## 8. 小结

- 多 Pass `EquipmentUV` 可以在 **单 Renderer 内** 同时绘制角色本体和基于 UVMap 的「贴合轮廓阴影」。
- 阴影强度/大小基于 **帧内脚部像素位置 + 全局地面基准**，与动画名解耦。
- 武器和斗篷等复杂部件仍然建议保持 **子对象 SpriteRenderer** 结构：
  - 符合主流商业项目的工程实践；
  - 可以按需为它们增加简易「附带阴影」Shader，而不必强行并入主 Shader 管线。
